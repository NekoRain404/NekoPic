# 性能审计（2026-11-05）

基于 `bench_pipeline --quick --jobs 1`（串行，减少并发干扰）与代码路径审计。共享主机、负载约 3；数字用于比较量级，不是硬件承诺。
完整基准：`native/tests/bench_pipeline.cpp`，已扩展到 13 款滤镜与高级调色用例；历史数据见 `docs/performance.md`。

## 1. 关键测量（中位数）

| 场景 | 2 MP | 8 MP | 说明 |

| 基础曝光 +1 | 5.3 ms | 17.8 ms | 已优化路径，接近内存带宽 |
| 单色滤镜 | 14.3 ms | 57.9 ms | 逐像素亮度/交叉通道 |
| 高光 + 阴影 | 24.3 ms | 99.1 ms | 高级调色 |

## 2. 结论

### 已经很好
- 基础调色：查找表 + 融合滤镜 + 行并行，2 MP 曝光 5 ms、8 MP 18 ms，已不是瓶颈。
- 色彩变换、历史记账、UI 渲染没有明显异常。
- GPU 基础拖动预览可用。

### 主要瓶颈（按影响排序）

1. **高级调色整图 CPU 重算**：HSL、色彩分级、细节/效果每帧都在完整底图上执行；8 MP 高级组合约 0.66 s，2 MP 约 0.17 s。拖动滑杆时 CPU 预览排队，交互会“追不上手”。
2. **对象编辑重复整图渲染**：文字/形状/笔迹每次提交都重新执行 `Adjustments::apply(base, params)` 再合成对象（`composeImage`）。高级参数下移动一次文字可能数百毫秒。
3. **13 款滤镜缩略图串行生成**：每批 34–41 ms，其中 13 次预设应用串行；按当前照片更新时仍可感知。缩略图只需 8 位、低分辨率。
4. **RGBA8 马赛克路径**：12 MP 同 ROI 下 145–167 ms，而 RGBA64 约 40 ms；`pixelColor/setPixelColor` 构造 QColor 是明显浪费。
5. **历史预算**：大图只能保留极少撤销步；48 MP 可能一步都没有，且没有明确提示。
6. **GPU 预览覆盖窄**：仅曝光/亮度/对比度/饱和；高光/阴影/白平衡/自然饱和度/曲线仍走 CPU。

## 3. 建议优化（按收益/成本）

| 优先级 | 优化 | 预估收益 | 成本/风险 |
| --- | --- | --- | --- |
| P0 | **交互预览改为显示分辨率代理**：拖动时在 ≤1600×1000 代理图上计算，松手后用全尺寸提交 | 8 MP 高级预览从 ~0.66 s 降到 ~15–30 ms；手感质变 | 中；需保证最终提交仍全尺寸、撤销一步 |
| P0 | **缓存调整后的底图**：`adjustedCache = apply(base, params)`；对象增删/移动只重合成对象；参数/底图变化才失效 | 对象编辑从数百 ms 降到对象合成（通常 <20 ms） | 中；需管理缓存与历史一致性 |
| P1 | **并行生成 13 张滤镜缩略图**（线程池/每张一个任务）并缓存 192×144 底图；仅对缩略图使用 8 位快速路径 | 批次 35–40 ms → 约 8–15 ms | 低–中 |
| P1 | **扩展 GPU 预览**：高光/阴影/白/黑、白平衡、自然饱和度、曲线 LUT | 常用高级滑杆即时反馈 | 中；着色器与 CPU 一致性测试 |
| P1 | **马赛克 RGBA8 直接像素操作** | 12 MP ROI 2–3 倍 | 低 |
| P2 | 历史快照压缩/分块或提高预算 + UI 提示 | 大图可撤销步数增加 | 中–高 |
| P2 | 高级效果的 LUT/近似（HSL 色带、分级掩码、局部对比缓存） | 单阶段 20–40% | 高；需质量回归 |
| P3 | 解码/格式：保持 Qt，除非有实测瓶颈；Rust 已评估无优势 | — | — |

## 4. 不建议现在做的

- 不改基础调色路径：已接近内存带宽，继续优化收益小。
- 不引入 libvips/G'MIC：当前瓶颈是算法与调度，不是解码库。
- 不为每帧新建线程/任务；先做代理预览与缓存，统一任务取消与预算。

## 5. 验收建议

- 增加“拖动到松手”的端到端交互基准（代理预览 + 全尺寸提交分开计时）。
- 对 2/8/12 MP 的高级调色、对象移动、滤镜批处理设置 p95 预算。
- 在真实显示器上测输入到像素反馈延迟，而不只测 CPU 函数时间。
