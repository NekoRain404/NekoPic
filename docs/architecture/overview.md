# NekoPic 架构总览

状态：v1 方向文档，2026-11-05。本文定义长期边界与协作规则；当前已实现能力以 `HANDOFF.md` 和代码为准。

## 1. 产品意图

NekoPic 是 Linux 优先的桌面照片编辑器：接近手机相册的常用编辑闭环，同时保留桌面菜单、快捷键、文件工作流和精细操作。视觉与交互参考根目录 H5 原型，但原生版以真实像素处理、数据安全和性能为验收标准。

成功的样子：打开大图不卡界面；拖动滑杆即时反馈；保存可靠；中文/英文与深浅主题完整；新增工具不需要改控制器核心；模块可并行开发而不互相踩踏。

## 2. 技术基线

| 维度 | 决策 |
| --- | --- |
| 主语言 | C++20，核心算法与文档模型 |
| UI | Qt Quick / QML，Qt 6.5+；视觉系统集中在 `qml/UI` |
| 构建 | CMake + Ninja；模块化目标，测试默认开启 |
| Rust | **仅在有可测量优势时引入**，独立静态库 + 稳定 C ABI + 可选构建开关，不做默认依赖 |
| 硬件加速 | 交互预览优先 GPU（RHI 着色器），CPU 为权威结果与回退路径 |
| 格式 | 能力注册表驱动；读写支持以实际编解码器为准，不按扩展名承诺 |
| 平台 | Linux 优先；平台差异收敛在 `src/platform` |
| 国际化 | Qt 翻译 + 源字符串英文；语言/主题偏好持久化 |
| 版本管理 | Git 分支开发、原子提交、可回滚里程碑 |

## 3. 分层与依赖方向

```text
QML 外壳 (qml/)
    ↓ 只调用公开属性/命令
应用层 (src/app/)            DocumentController、FilterPreviews、Theme/Language
    ↓
领域层 (src/document/)       文档状态、命令事务、历史、对象模型（演进中）
    ↓
服务层 (src/io/, render/)   格式、元数据、异步任务、GPU/CPU 预览后端
    ↓
核心层 (src/core/)           纯图像算法；只依赖 Qt Core/Gui 值类型
```

规则：

1. 依赖只能向下。`core` 不认识 QML、控制器、文件对话框。
2. QML 不直接读写像素或文件，只发命令、读状态。
3. 后台线程只处理不可变快照；GUI 线程提交结果并发出通知。
4. 每个异步结果携带文档 ID + 修订号 + 请求号；过期结果丢弃。
5. 新能力先定接口与测试桩，再并行实现，避免多人改同一核心文件。

## 4. 并发与线程契约

- `DocumentController` 及其可观察状态留在 GUI 线程。
- 耗时任务使用 `QtConcurrent::run` + 不可变 `QImage` 快照 + `QFutureWatcher`。
- 单个文档同一时刻只允许一个同类 worker（调色、缩略图、几何各自约束）。
- 保存期间禁止继续编辑；若未来放开，必须以「实际保存快照的修订号」更新保存点。
- 取消/进度/错误码统一进入任务服务（演进目标），不在各工具里各自发明。
- 任何 worker 不得捕获可变 GUI 对象。

## 5. 渲染与硬件加速

- 交互拖动时，GPU 着色器基于**底图**即时显示待提交参数，避免每帧 CPU 往返。
- 松手后由 CPU 生成权威像素，进入撤销历史并替换预览。
- GPU 预览只在安全条件下启用：非软件后端、无滤镜叠加、着色器能力可用；否则自动回退 CPU。
- GPU 与 CPU 使用同一参数公式；像素一致性有容差测试，导出永远不依赖未验证的 GPU 结果。
- 未来可把预览后端抽象为 `RenderBackend`（CPU / RHI compute），接口先行。

## 6. 格式与元数据

- `FormatRegistry` 汇总 Qt 插件与可选提供者的读写能力，生成文件对话框过滤器和能力矩阵。
- 解码前检查尺寸/像素预算；解码后再校验。
- EXIF 方向、ICC、透明度、位深按「实际能力」报告；不得把保留标签称为完成色彩管理。
- 首批输出仍为 PNG / JPEG；扩展格式需逐项样例验证后再公布。

## 7. Rust 边界（证据驱动）

Rust 不进入 UI、文档状态和主渲染链路。候选场景只有三类：

1. 解析不可信元数据（EXIF/ICC）时的内存安全与模糊测试收益；
2. Qt 插件缺失格式的解码补充；
3. SIMD 重采样/缩略图在基准上显著优于 Qt 的实现。

准入条件：有基准数据、有 CPU/Qt 回退、有 C ABI 与所有权约定、构建可关闭、许可可分发。没有证据就不引入。详见 ADR-0002。

## 8. 视觉与交互（Apple 质感）

- 单一设计令牌源（颜色、间距、圆角、字号、阴影、动效），禁止组件内散落魔法值。
- 8pt 间距网格；克制的层次与对比；柔和的表面与阴影；重点色只用于行动与选中。
- 动效 120–280ms，标准缓出；按压 0.98 缩放、悬停轻提亮；支持减少动效设置。
- 键盘焦点、可访问名称、禁用态、忙态、深浅主题在所有自定义控件中一致。
- 详见 ADR-0004 与 `qml/UI`。

## 9. 非目标

- 不做可编辑工程文件格式（恢复快照不等于工程格式）。
- 不在首阶段承诺 RAW、动画、多页、HDR 显示或全链路 ICC。
- 不为并行而拆分模块，不提前空壳化架构文档中的所有服务。
- 不把 H5 的展示型参数当作已实现功能。

## 10. 验收门槛

每个增量必须同时满足：构建无新增警告；相关 C++/QML 测试通过；失败路径有提示；线程与坐标契约写清；文档更新「已实现/未实现/未验收」三种状态；真实显示器抽查视觉与流畅度（条件允许时）。
