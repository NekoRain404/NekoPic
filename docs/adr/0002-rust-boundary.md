# ADR-0002：Rust 仅作为证据驱动的可选模块

状态：已采纳（2026-11-05）

## 背景

产品路线允许在 Rust 有优势的地方使用 Rust，但主技术栈是 C++20。无证据地引入第二语言会增加构建、调试、分发和协作成本。

## 决策

Rust 默认不参与构建。只有满足以下全部条件才可作为独立静态库加入：

1. 存在可测量的优势：基准、质量或安全性数据，而非语言偏好；
2. 有明确的 CPU/Qt 回退，关闭 Rust 时产品仍可用；
3. 通过稳定 C ABI 交互，所有权、错误、线程规则写清；
4. CMake 开关可控（如 `NEKOPIC_WITH_RUST=OFF` 默认关闭或按基准结论决定）；
5. 许可证与分发依赖经过核对。

允许的候选场景：

- 解析不可信 EXIF/ICC 等元数据（内存安全、可模糊测试）；
- Qt 插件缺失格式的解码补充；
- SIMD 重采样/缩略图，且基准显著优于 Qt 实现。

禁止：Rust 进入 QML/UI 主链路、文档状态机、默认导出路径；禁止为并行而拆分。

## 后果

- 没有基准就不合入 Rust 代码；
- 每个 Rust 模块必须附带 C++ 回退测试与关闭构建的 CI 路径；
- 若基准不支持，保留调研记录并删除实验代码，避免长期维护空壳。


## 评估结论（2026-11-05）

按本 ADR 的门槛完成基准评估，结论为**暂不引入 Rust**：

- Qt 6.12 在本环境读取 101 种格式、写出 38 种，是 `image` crate 的超集；
- Qt 已通过 `QImageReader::transformation()` 与 `QColorSpace` 覆盖方向与 ICC；
- SIMD 缩放在 12 MP、≥512px 目标上有 1.3–2.3 倍优势，但当前唯一调用点是
  192×144 缩略图，收益不足 1 ms，且大目标下质量不等价；
- JPEG 解码无 >20% 优势；PNG 解码虽快 2.27 倍，但会替换 Qt 默认路径并引入重依赖。
