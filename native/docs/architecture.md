# 原生端架构与实施路线

本文是设计与协作约定，不是功能完成清单。根目录的 H5 是界面和交互原型，不能作为原生图像质量、色彩管理或数据可靠性的证明。首阶段采用 Qt Quick / QML 界面、C++20 核心和 CMake；具体支持的平台、依赖版本及发布格式在构建验证后确定。

## 模块与所有权

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| 应用外壳 | 窗口、菜单、快捷键、文件对话框、设置、翻译和主题 | QML 只通过公开的 C++ 状态和命令操作文档，不直接改像素或读写文件 |
| 文档与命令 | 源图、非破坏性参数、对象、画布几何、修订号、撤销/重做和脏状态 | 文档是唯一权威状态；一次笔画、滑杆拖动或文字编辑各形成一个撤销事务 |
| 图像管线 | 解码、方向与色彩转换、调色和滤镜、对象合成、缩放及输出 | 接收不可变文档快照；预览与导出共享参数和处理顺序，质量等级可不同 |
| 渲染与调度 | 视口、缩放平移、预览任务、缓存、取消和 GPU 能力探测 | 异步结果携带文档 ID、修订号和请求 ID；过期结果丢弃，后台线程不直接修改 UI |
| 文件与恢复 | 格式探测、导入、导出、原子替换、最近文件和恢复快照 | 保存和恢复是不同机制；合并图片不等于可编辑工程文件 |
| 平台适配 | 剪贴板、显示器色彩配置、输入设备及系统集成 | 平台差异收敛在此，未验证的能力不可声称支持 |

依赖方向为 QML 外壳 → 应用控制器 → 文档、管线及文件服务；核心不依赖 QML 控件。C++ 拥有文档和异步任务生命周期，Qt 主线程发布界面可观察状态。不要让 QML 或 GPU 纹理成为唯一图像数据来源。

## 并行开发接口

以下为待实现的契约，不代表已有 API；实现前由接口负责人统一类型、错误码和线程约束。

- `DocumentSnapshot`：不可变的文档 ID、递增修订号、源图引用、尺寸、对象、调整参数与色彩描述。坐标和单位明确为图像像素；旋转/翻转作用于图像与对象，裁剪移动坐标并裁切，图片缩放同步缩放对象，画布尺寸单独调整。
- `DocumentController`：执行命令及事务、撤销/重做、返回快照并通知状态。保存成功只把实际保存的修订号标为已保存；保存期间产生的新编辑仍为脏状态。
- `ImageService`：异步打开、请求预览及导出；请求包含快照、目标尺寸、色彩目标、质量和取消令牌，结果包含对应 ID、修订号、状态和结构化错误。任务失败或取消不得改变文档。
- `FileService`：探测格式与能力、读取元数据、保存指定快照和报告结果。输出选项明确格式、质量、透明背景、色彩空间和元数据策略，不能仅依赖文件扩展名。
- `UiState`：只暴露可观察状态、可用操作、进度和错误；不支持的操作禁用或说明。QML 和核心的集成先使用可替换的服务接口及测试桩，避免并行修改内部实现。

## 图像质量和资源

管线目标为：解码并应用 EXIF 方向 → 根据嵌入 ICC 转换到明确的工作色域 → 调整与滤镜 → 对象合成 → 转换到显示或输出色域。无配置文件、损坏配置文件和不支持配置文件须有明确回退与提示；不能把广色域数据直接当作 sRGB。显示器配置、渲染意图、位深及 alpha 合成规则需要实测和记录。先保证可信的 sRGB 路径，再逐步验证广色域与高位深；不声称现阶段已实现全链路 ICC。

PNG、JPEG、WebP 为首批目标，按实际编译的编解码器公布读写能力；JPEG 无透明通道，导出时提供背景。EXIF、ICC 和其他元数据的保留、剔除或重写须按格式明确，避免方向重复应用或隐私信息意外泄露。其他格式、动画和多帧图像须单独设计，不以扩展名推断已支持。libvips 可作为基础处理与 ICC 的验证候选；libgmic 和 LUT 属于后续评估，需核对许可证、色域、性能和分发依赖。

CPU 路径是可验证的基准和 GPU 不可用时的回退。GPU 用于有收益的交互预览，需探测设备能力、处理设备丢失并可回退；导出不得依赖未经验证的 GPU 结果。相同输入与参数下以定义的容差比较 CPU、GPU 预览和最终输出，避免过期预览覆盖新结果。

以原型限额作为初始预算：32 MP、单边 8192 px、最多 80 条或约 128 MiB 历史、每笔最多 4096 个采样点。这些不是原生性能保证；导入前检查尺寸和内存估算，对解码膨胀、缓存、并发和大图导出设硬上限，提供可理解的失败信息。按真实设备测量后调整，避免静默丢失编辑。

## 保存、恢复与体验

保存/另存为输出合并图，窗口内仍保留可编辑对象；重新打开输出时为合并图。编码到目标目录的临时文件，检查写入、刷新和关闭错误，成功后采用平台支持的原子替换；失败保留原目标并报告，必要时处理权限、空间不足、跨文件系统及外部修改冲突。具体持久化保证按平台验证，不把原子替换等同于断电后绝对安全。保存以快照为单位，成功前不清除脏状态。

恢复快照应有版本、完整性检查、写入限额和清理策略，并允许用户选择恢复或丢弃；它是尽力恢复，不是备份或正式工程格式。工程文件的版本、迁移和兼容性另行设计。

界面文字使用 Qt 翻译机制，首批规划简体中文和英文；动态内容、快捷键及可访问名称也须覆盖，切换语言和主题应刷新界面并持久化偏好。深浅主题使用统一语义色和控件状态，在真实显示器、高 DPI 和键盘操作下验证；主题不改变图片像素。压力笔、打印、命令行和文件关联均需独立平台验证。

Rust 不是首阶段依赖。只有在存在明确收益的独立库或安全边界时再评估，通过稳定 C ABI 封装所有权、错误及线程规则，并验证构建和分发成本；不为语言而拆分核心。

## 阶段与验收

1. **基础壳层**：Qt Quick / C++20 构建、窗口、布局、主题、翻译骨架、文档状态和可替换服务接口。验证启动、缩放、键盘导航与基本构建；界面演示不冒充图像处理完成。
2. **可信基础编辑**：实现受限格式导入、方向处理、sRGB 显示、几何操作、命令历史、合并导出和可靠保存；对错误和资源上限提供反馈。以像素样例、修订号和失败注入验证。
3. **质量与性能**：验证 ICC、元数据、预览与导出一致性、大图预算、CPU/GPU 一致性及回退，按测试结果决定支持矩阵。再逐步接入调色、滤镜、文字、绘制与恢复，逐项验证和公开限制。
4. **平台与发布**：多语言与主题完整性、设备输入、平台集成、打包和升级测试；以平台实际验证结果决定发布范围。

测试包括文档命令与撤销事务、异步取消及过期结果、格式/透明度/方向/ICC 样例、预览与导出像素比较、保存中编辑及写入失败、损坏输入与资源边界，以及 QML 交互和真实显示器检查。每项能力须有对应样例、误差容限和已测平台记录。

当前这些阶段均为计划。H5 中的高级调色有仅供交互展示的参数；原生图像引擎、专业 ICC、可靠保存、工程格式、恢复、GPU 加速、多语言及平台功能均不可仅凭原型或本文视为已完成。
